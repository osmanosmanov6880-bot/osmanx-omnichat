# OSMANX OMNICHAT R26 — защита всей компании при инциденте

**Дата релиза:** 5 ноября 2026 года. **Тип:** локально проверенная инженерная сборка, не production SaaS.

## Что действительно реализовано

**Аварийная остановка новых исходящих всех каналов одной компании** из раздела «Контроль доставки». Доступна только владельцу или администратору рабочей области, но не менеджерам и операторам. Действие требует явного подтверждения и одного из ограниченных кодов причины. Значения сохраняются в SQL и фиксируются в журнале аудита.

Во время паузы:

- исходящие задания **всех каналов этой компании** не выбираются из очереди перед LIMIT;
- после захвата обработчиком состояние компании дополнительно проверяется;
- последняя SQL-контрольная точка непосредственно перед внешним HTTP-запросом проверяет как паузу аккаунта R25, так и паузу компании R26;
- захваченные **до начала отправки** задания возвращаются в очередь без израсходованной попытки;
- входящие webhooks, чат сайта и работа **других компаний** продолжаются;
- сообщения, уже прошедшие контрольную точку до паузы, **могут быть отправлены**: внешние вызовы нельзя отозвать задним числом;
- сообщения с неопределённой доставкой **не повторяются автоматически**.

Возобновление требует актуальной отметки времени паузы (optimistic compare-and-swap). Если другой администратор изменил состояние, старое действие получает HTTP 409. Снятие общей паузы **не снимает** индивидуальные паузы аккаунтов или cooldown сторонней площадки.

В интерфейсе отдельная спокойная секция отображает текущий статус и только одно основное действие. В Inbox оператор видит предупреждение, что ответ останется в очереди.

## Файлы и совместимость

- `backend/app/company_pause.py` — роли, SQL CAS, аудит, API `POST /api/operations/outbound/pause` и `/resume`.
- `backend/app/services.py` — tenant-aware выбор очереди, отображение статуса в диалогах, preflight.
- `backend/app/outbox_recovery.py` — последняя SQL-проверка и безопасный возврат незапущенной отправки.
- `backend/app/operations.py` — агрегированный статус компании.
- `backend/alembic/versions/f26000a10001_tenant_outbound_pause.py` — добавляет три nullable-поля в `organizations`; исходные сообщения и каналы остаются без изменений.
- `frontend/src/app.tsx`, `frontend/public/styles.css`, `frontend/public/app.js` — русскоязычный интерфейс R26.
- `backend/tests/test_r26_global_incident_pause.py` — 12 новых сценариев, включая конкуренцию и очередь другого арендатора.
- `scripts/browser_r26_company_pause.py` — Chromium + локальный FastAPI, 1512/390/320px.
- `scripts/verify_r26_postgres.py` — реальный PostgreSQL CAS-тест для отдельного CI job; **не исполнялся в текущем контейнере**.

## Принципиальные ограничения

1. Реальные PostgreSQL 16 и Docker локально не доступны. Скрипт и отдельный шаг в GitHub Actions подготовлены; **нельзя объявлять Postgres-конкуренцию пройденной до исполнения workflow**.
2. npm registry отвечает `EAI_AGAIN`. Проверенный интерфейс по-прежнему использует vendored React 16; React 19/Vite остаётся **неактивированной кандидатной сборкой**.
3. Сквозные отправки WhatsApp/Instagram/Авито/Telegram/VK/MAX не выполнялись — нужны официальные разрешения, токены и HTTPS.
4. Независимый аудит безопасности и нагрузочное тестирование не выполнены.
5. Публикация, платежи и монетизация не изменялись.

## Обновление R25 → R26

1. Остановить API и **все** фоновые worker-процессы R25. Не запускать старую и новую версии одновременно на одной БД.
2. Создать и **проверить** резервную копию текущей БД (`backup_local_windows.bat` / `backup_local_linux.sh`). Не включать копию и `.env` в ZIP.
3. Отдельно распаковать R26 и перенести конфигурацию секретов только через защищённое окружение.
4. Выполнить `alembic -c backend/alembic.ini upgrade head` для `f26000a10001`, затем `alembic -c backend/alembic.ini check`.
5. Запустить `start_windows.bat` или `./start_linux.sh`, проверить «Контроль доставки» на реальной организации. Деморежим не требует аварийной остановки.
6. Для коммерческого production сперва проверить настоящие PostgreSQL, внешние API и восстановление после аварии.
