# Центр управления: правила, права и API

## Назначение

`GET /api/command-center` помогает оператору видеть следующую важную переписку и руководителю понимать текущую нагрузку. **Никакая AI-модель не используется**: оценки вычисляются из подтверждённых полей БД. Чужие компании и чужие назначенные диалоги исключаются на уровне SQL.

## Приоритетные баллы

Основа оценки: `Срочно` = 65, `Высокий` = 35, `Обычный` = 12, `Низкий` = 0.

- Если последнее сообщение клиента не имеет более позднего исходящего ответа и срок не превышен: **+12**.
- Если SLA превышен: **+35** плюс до **+25** за дальнейшее ожидание (по 1 баллу за каждые 5 минут после порога).
- За непрочитанные: **+5 за сообщение**, максимум +15.
- Если ответственный не назначен: **+10**.

Результат сортируется по баллам и времени последнего сообщения. Каждому кандидату API возвращает человекочитаемые причины (`reasons`) и минуты ожидания (`minutes_waiting`). **Баллы — приоритет обработки, не оценка клиента и не прогноз сделки.**

При одной секунде равенства timestamps выборка может использовать неопределённый порядок; строгий tie-breaker следует добавить до эксплуатации на очень больших объёмах.

## Ограничение области данных

API рассматривает до 500 последних активных, не архивных диалогов, доступных сотруднику; максимум 25 кандидатов возвращаются в `priority_queue`. Поля `total_open`, `overdue`, `waiting`, `unread`, `unassigned` относятся к этим 500, а не ко всем историческим обращениям организации. Параметр `scope=latest_500_open_conversations` позволяет явно отличать ограниченный обзор от абсолютных показателей. Для больших контакт-центров нужен фоновый агрегатор и курсорная пагинация.

## API

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/command-center` | Область видимости, метрики, приоритетная очередь, нагрузка |
| GET | `/api/views` | Собственные и общие сохранённые подборки |
| POST | `/api/views` | Создать подборку; `name`, `filters`, `shared` |
| DELETE | `/api/views/{id}` | Удалить собственную или разрешённую подборку |
| PATCH | `/api/conversations/{id}/priority` | Изменить приоритет; `priority`, `expected_version` |
| GET | `/api/conversations/{id}/activity` | Журнал действий по доступному диалогу |
| GET | `/api/conversations?priority=urgent&sort=priority` | Текущие фильтры и сортировка на сервере |

Допустимые фильтры подборки: `channel`, `status`, `priority`, `assigned`, `archived`, `sort`. SQL-выражения и произвольные поля запрещены. Создавать общие подборки могут владелец, администратор и руководитель. Пользователь не может открыть чужой диалог через подборку. Все действия с приоритетами/подборками регистрируются в `AuditLog`.

`expected_version` сравнивается в одном SQL `UPDATE`; если второй сотрудник опередил первого, сервер отвечает **409** и требует обновить данные. Контроль временного захвата диалога из v0.3 продолжает работать независимо.
