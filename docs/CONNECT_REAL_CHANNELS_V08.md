# Как подключить настоящие аккаунты — OSMANX OMNICHAT v0.8

**Цель:** владелец каждой компании подключает **свои разрешённые бизнес-аккаунты, страницы или боты**. В едином Inbox появляются только сообщения, доступные официальному API. Это **не доступ к личным чатам** сотрудника в Telegram, WhatsApp, VK или Instagram.

## Две стороны настройки

**Администратор OSMANX делает один раз для всей платформы:**

1. Получает домен и публичный сервер HTTPS 443 с валидным сертификатом. Устанавливает `PUBLIC_BASE_URL=https://chat.company.example`, без лишнего пути.
2. Настраивает production PostgreSQL, `INTEGRATION_ENCRYPTION_KEY` (Fernet), `APP_ENV=production`, `COOKIE_SECURE=true`, резервные копии. Не публикует `.env` и секреты.
3. Регистрирует и, где необходимо, согласует интеграционные приложения Meta/Авито; заполняет App ID/Secret и webhook verify token **только на сервере**. Клиентам App Secret выдавать нельзя.
4. Запускает безотправочную проверку `python scripts/check_live_setup.py` — она говорит только о синтаксической готовности конфигурации; не проверяет сеть, договоры и права Meta/Авито.
5. Проверяет миграции `PYTHONPATH=backend alembic -c backend/alembic.ini upgrade head`; проверяет HTTPS-сертификат, callback и подписи входящих.

**Предприниматель делает для своей компании:**

1. Регистрируется в OSMANX под собственным рабочим пространством.
2. Открывает **Интеграции**, выбирает площадку и читает «Что требуется для подключения?».
3. Нажимает «Подключить» — проходит OAuth или вводит **токен своего разрешённого бота/сообщества**. Токен сохраняется зашифрованным сервером; приложение не хранит его в браузере.
4. Если нужно, нажимает **Настроить события**. Для Telegram/MAX можно нажать **Проверить webhook у сервиса** — OSMANX сверит точный URL с официальным API.
5. Пишет реальное контрольное сообщение через исходную площадку, видит его во «Входящих», отвечает из OSMANX, проверяет, что ответ действительно появился в оригинальном приложении.

## Четыре статуса — только подтверждённые факты

| Шаг | Доказательство | Когда нельзя показывать «готово» |
| --- | --- | --- |
| **1. Доступ к аккаунту** | Официальный API подтвердил аккаунт/бот | Токен отсутствует/отозван, OAuth не завершён |
| **2. Получение событий** | Подписка Telegram/MAX подтверждена удалённым API, другие webhooks/синхронизация зарегистрированы | У провайдера другой callback URL, не настроен HTTPS/события |
| **3. Входящее получено** | Сохранено настоящее входящее через проверенный webhook или синхронизацию | Только тестовая демопереписка или пустой Inbox |
| **4. API принял ответ** | Сервер получил подтверждение отправки от внешнего API **после подключения текущего токена** | Сообщение лишь поставлено в очередь, сеть оборвалась, внешний API ответил ошибкой |

**Важно:** шаг 4 не подтверждает доставку клиенту, отображение в его мессенджере или прочтение. Проверка в оригинальной площадке обязательна. После смены токена доказательство исходящего сбрасывается, а после обычной проверки токена — сохраняется.

## Каналы и особенности

| Канал | Что клиент подключает | Как приходят новые сообщения | Главное ограничение |
| --- | --- | --- | --- |
| Telegram | Свой бот от `@BotFather` | `setWebhook` + секретный заголовок + `getWebhookInfo` | Личные чаты произвольного аккаунта не доступны |
| MAX | Свой разрешённый бот | POST `/subscriptions`, GET `/subscriptions`, подписанный webhook | HTTPS порт 443 и доверенный сертификат, не личный аккаунт |
| ВКонтакте | Сообщество VK с разрешениями на сообщения | Callback API, код подтверждения, секрет | Не личные сообщения обычного профиля |
| WhatsApp | Номер WhatsApp Business Platform / WABA | Cloud API и Meta webhook | 24-часовое окно ответов; вне окна нужны утверждённые шаблоны (в этом релизе не завершены) |
| Instagram | Профессиональный Instagram и разрешённое Meta App | Instagram Login, подписка на события DM | Не личный Instagram и не неограниченная история |
| Facebook Messenger | Facebook Page с доступом к сообщениям | Meta Page OAuth / subscribed_apps | Не личный Messenger профиля |
| Авито | Бизнес-аккаунт с доступом Messenger API | Разрешённая синхронизация API | Требует официальный доступ/соответствующий тариф |
| Сайт-чат | Встраиваемый собственный виджет | Защищённые сессии OSMANX | Для публичного сайта нужен HTTPS |

Официальные ссылки: [Telegram Bot API](https://core.telegram.org/bots/api), [MAX подписки](https://dev.max.ru/docs-api/methods/GET/subscriptions), [MAX регистрация webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions), [Meta разработчикам](https://developers.facebook.com/docs/), [Авито API](https://developers.avito.ru/).

## Если что-то не работает

- **«Токен проверен, но не подключено»** — нормально. Осталось настроить события и проверить настоящий входящий.
- **«Webhook у сервиса другой»** — нажмите «Настроить события» или укажите правильный HTTPS callback. Проверьте совпадение домена и SSL.
- **«Входящих нет»** — убедитесь, что пишете именно боту/странице, что установлена подписка, у аккаунта есть права и отправитель разрешён платформой.
- **«Ответ ожидает отправки»** — проверьте worker и очередь, доступ к внешнему API. Не отправляйте вторично вслепую после тайм-аута: возможно, площадка приняла первое сообщение.
- **«Отправлено» внутри OSMANX, но клиент не видит** — статус «API принял» не равен доставке; сверяйтесь с оригинальной площадкой и её ограничениями.
- **Meta App Review ещё нет** — завершение массового подключения невозможно без разрешения Meta. Никакая имитация авторизации не решит проблему.
- **«Отключить канал»** — для Telegram и MAX OSMANX сначала отзывает webhook на стороне площадки и проверяет результат; если сервис недоступен, сохранит ключ для повтора. В остальных каналах после отключения обязательно отзовите разрешения приложения и webhooks в кабинете самой площадки.
- **Мобильный OSMANX работает, но браузер не получает уведомления** — это отдельная задача настройки домена, HTTPS и разрешений уведомлений.

## Самопроверка без боевых ключей

```bash
PYTHONPATH=backend pytest -q backend/tests
python scripts/check_live_setup.py
# Скрипт вернёт код 1, пока сервер не подготовлен — это правильно.
tsc --project frontend/tsconfig.json
python scripts/onboarding_v08_e2e.py
```

Сценарий Chromium использует настоящие локальные React и FastAPI, а **внешние ответы Telegram в нём подменены тестовыми контрактными ответами**, без обращения к реальному аккаунту.

**Только после согласованных интеграционных испытаний:** серверное развёртывание, поддерживаемый React, мониторинг, нагрузка, резервное восстановление, юридические вопросы хранения персональных данных и клиентские пилоты. По просьбе владельца публичный запуск и платёжные провайдеры сейчас не выполняются.
