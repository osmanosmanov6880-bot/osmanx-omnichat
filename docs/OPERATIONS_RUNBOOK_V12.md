# Контроль доставки: короткая инструкция для руководителя

В OSMANX откройте **«Другие разделы» → «Контроль доставки»**. Сначала прочитайте блок **«Что сделать сейчас»**. Ниже система показывает реальные статусы, сохранённые сервером.

| Надпись | Значение | Что делать |
| --- | --- | --- |
| В очереди | Ответ сохранён в базе, отправка ещё не началась | Подождать и проверить активность обработчика |
| Отправляется | Фоновый обработчик выполняет запрос к API | Не нажимать «Отправить» повторно |
| Принято API | Площадка приняла запрос | Не считать автоматически доставленным на устройство клиента |
| Требует проверки | После сетевого сбоя неизвестно, получил ли сервис запрос | Открыть оригинальную соцсеть, сверить переписку и сохранить доказательство проверки |
| Ошибка | Отправка не подтверждена из-за ошибки | Изучить причину и состояние канала, повторное действие — только после проверки |
| Доставлено / Прочитано | Подтверждено соответствующим событием площадки, если она его предоставляет | Никаких дополнительных действий не требуется |

**Особенно важно:** при статусе «Требует проверки» OSMANX намеренно **не пересылает** сообщение автоматически, чтобы клиент не получил два одинаковых ответа. Владелец или администратор может записать результат сверки в журнал; это не имитирует получение нового webhook.

Каждая компания видит только свои каналы и сообщения. Если вы работаете с несколькими компаниями, переключение рабочего пространства не объединяет их сообщения и токены.

Служебные показатели — это не обещание надёжности внешнего API. Для реального подключения нужны официальный тип аккаунта, необходимые разрешения, корректный webhook и двусторонняя проверка с согласия владельца аккаунта.
