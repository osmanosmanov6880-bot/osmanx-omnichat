# React 19.3 / Vite 8 — подготовленный переход (пока не активирован)

В текущем v1.4 работают локальные проверенные файлы в `frontend/public/`, использующие React **16**. Из-за недоступного npm-реестра в среде сборки новый runtime React 19 **не загружен и не заявляется готовым**.

Подготовлен **отдельный** entrypoint `frontend/src/modern-entry.ts` с `ReactDOM.createRoot` и сборка Vite. Большой существующий React-класс Inbox переиспользуется как есть; его UI не переписывается и не дублируется. Это промежуточный адаптер, а не окончательная модульная архитектура.

На машине с доступом к npm:

```bash
cd frontend
npm install --no-audit --no-fund
npm run typecheck:modern
npm run build:modern
```

Результат должен появиться в `frontend/public/modern/`. **Не** выставляйте `FRONTEND_MODE=modern`, пока не прошли эти команды, браузерные тесты для входа, Inbox, отправки и интеграций, CSP и сканирование зависимостей. После них можно локально включить экспериментальную сборку переменной:

```text
FRONTEND_MODE=modern
```

Установка React 19 и Vite 8 из `package.json` требует Node 22.12+ и доступа к registry. В архиве **нет** `package-lock.json` — в офлайн-среде его не удалось честно получить. При первом подключении к сети создайте lockfile и зафиксируйте его в Git, затем используйте `npm ci` в CI и деплое. Сейчас CI-кандидат устанавливает закреплённые прямые зависимости через `npm install`; транзитивные могут изменяться без lockfile.

**Шаги для выхода в production:** создать/зафиксировать lockfile; успешные CI и Chromium E2E на новой сборке; проверить лицензии; удалить React 16 и его `vendor`-бандлы; включить современную сборку по умолчанию; провести повторный аудит. До этого момента React 16 остаётся блокирующим техническим долгом для публичного SaaS.
