# Защита публичных API и обратный прокси — инструкция для владельца

## Кратко

С версии v1.3 регистрация компании, запуск деморежима и создание посетительской сессии виджета используют общие SQL-лимиты. Это работает даже при нескольких API-процессах, подключённых к одной PostgreSQL-базе.

По умолчанию для идентификации берётся сетевой адрес непосредственного клиента ASGI. Заголовок `X-Forwarded-For` **игнорируется**, пока его не передал явно доверенный прокси. Нельзя просто доверять заголовку от любого посетителя: он подделывается.

## Переменные окружения

- `INTEGRATION_ENCRYPTION_KEY` — обязательный production Fernet-ключ (его не нужно публиковать).
- `PUBLIC_RATE_LIMIT_SECRET` — необязательный отдельный секрет для HMAC идентификаторов лимита. Если пуст, используется `INTEGRATION_ENCRYPTION_KEY`.
- `TRUSTED_PROXY_CIDRS` — пустой по умолчанию. Заполнить только адресными сетями **своего** обратного прокси. Пример: `172.25.0.0/24`, но только если это реально назначенная сеть доверенного Caddy, а не вся сеть сторонних контейнеров.

Контейнер Uvicorn запущен с `--no-proxy-headers`, чтобы использовать проверку цепочки `X-Forwarded-For` в самом приложении. Администратор обязан контролировать, какие узлы имеют прямой сетевой доступ к API.

Если настроить CIDR неправильно, запросы всех посетителей за прокси могут попасть в один счётчик. Проверьте этот сценарий на staging до открытия публичного доступа.

## Ограничения и ответы

| Действие | Общее ограничение | При превышении |
| --- | --- | --- |
| Регистрация компании | 6 / час на источник | HTTP 429 + `Retry-After` |
| Создание демонстрационной компании | 12 / час на источник | HTTP 429 + `Retry-After` |
| Новая сессия виджета на одном сайте | 12 / час на источник | HTTP 429 + `Retry-After` |
| Текстовые сообщения из виджета | Отдельный лимит посетителя и SQL-квота | HTTP 429 |

Эти значения защитные и должны пройти нагрузочную и UX-проверку; для публичной платформы нужны также лимиты на балансировщике, наблюдаемость, автоматизированная оценка злоупотреблений и квоты внешних API.

## Восстановление после сбоя

Задания с неопределённым результатом не отправляются повторно. В разделе «Контроль доставки» сначала проверьте отправку в оригинальной соцсети, затем зафиксируйте результат с доказательством. Атомарный захват задания не означает подтверждённую доставку клиенту.

Новая система выбора заданий чередует компании внутри пакета. Она обеспечивает справедливый старт, но не создаёт дополнительных лимитов или привилегий во внешних сервисах.
