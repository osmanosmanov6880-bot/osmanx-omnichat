# R30 — что изменилось для оператора и владельца

**Пример:** клиент впервые пишет в Telegram сразу два сообщения — «Здравствуйте!» и «Сколько стоит доставка?». При нескольких серверах оба события могут обрабатываться параллельно.

**До R30** возможен конфликт при первом создании карточки клиента. **После R30** база данных разрешает гонку: одна карточка клиента, один диалог и два разных сообщения. Если провайдер пришлёт один и тот же message ID повторно, третье сообщение не возникнет, число непрочитанных не увеличится.

Сотруднику **не нужно нажимать новую кнопку**. Переписка продолжает открываться в привычном тёмном русскоязычном Inbox. Если чат уже был открыт во время прихода другого сообщения, защита прочтения R29 сохраняется.

Владельцу: перед обновлением требуется резервная копия базы и остановка старых серверов. Релиз не меняет настройки соцсетей или оплат. PostgreSQL-проверку четырёх конкурирующих процессов следует выполнить в изолированной среде до производственного запуска.

Технический тест для инженера: `PYTHONPATH=backend:. pytest -q backend/tests/test_r30_first_inbound_claim.py`. UI-проверка: `PYTHONPATH=backend:. python scripts/browser_r30_first_contact.py`.
