# OSMANX OMNICHAT R20 — масштабируемая история переписок

**Дата релиза:** 4 ноября 2026 года. **Статус:** локальная инженерная версия, не подтверждённая production SaaS. Продолжение **восстановленной R19**, а не побайтовой копии старого v1.8. Реальные аккаунты, публикация и платежи не подключались.

## Что исправлено

Ранее `GET /api/conversations/{id}` загружал первые 500 сообщений, отсортированных по возрастанию времени. Если у клиента больше 500 сообщений, новые ответы могли вообще **не появиться в открытой переписке**. Для предпринимателя и оператора это приводило к ошибочному впечатлению, что клиент не ответил.

**Теперь по умолчанию загружаются последние 120 сообщений**, в хронологическом порядке, а более ранняя история открывается кнопкой «Показать более ранние сообщения».

### Сервер

- `backend/app/history.py`: ограниченная выборка с курсором `before` по уникальному ID сообщения. Порядок по `(created_at, id)` предотвращает пропуски и дубли даже если сотни сообщений имеют одинаковые временные метки.
- Новый эндпоинт `GET /api/conversations/{id}/messages?before=<id>&limit=120`, максимум 200 за запрос. Выдаёт `messages`, `message_paging.has_older`, `message_paging.next_before`, `message_paging.page_size`.
- Эндпоинт применяет **те же ограничения организации и назначения оператору**, что и просмотр самого диалога. Курсор из чужого диалога или компании отклоняется (HTTP 404); попытка оператора открыть неназначенный диалог отклоняется (HTTP 403).
- Добавлен SQL-индекс `ix_message_history_cursor` и Alembic миграция `f20000a10001` поверх `f19000a10001`. Существующие сообщения, каналы и компании не изменяются.
- При первоначальном открытии сообщения всегда последние, а не самые старые. Полностью переписка продолжает храниться согласно действующей политике retention.

### Интерфейс

- Старую историю можно читать порциями, без загрузки тысяч сообщений при открытии каждого диалога.
- Во время добавления старых сообщений прокрутка сохраняет текущую позицию.
- При открытии нового диалога экран перемещается к свежим сообщениям; автоматическое 7-секундное обновление сохраняет ранее загруженные старые страницы.
- Цвета, типографика и мобильная композиция утверждённого тёмного интерфейса сохранены.

## Реальные проверки в среде сборки

- Серверные тесты: 650 сообщений в одном диалоге, повторяющиеся временные метки, приход нового ответа в процессе чтения истории, запрет чужого курсора, запрет неназначенного диалога для оператора.
- Браузер Chromium с реальным React UI и FastAPI TestClient: диалог с 330 архивными сообщениями, первоначальные 120, две подгрузки, сохранение старой истории после опроса сервера, ПК 1512 px, телефоны 390/320 px, контроль горизонтального переполнения и ошибок JavaScript.
- TypeScript: `tsc --project frontend/tsconfig.json`.
- Alembic: обновление R19 → R20 с сохранением компании и канала, `alembic check` без расхождений.
- Остальные тесты из R19 выполняются повторно в рамках проверки регрессии.

## Как запустить / обновить

Windows: распаковать ZIP отдельно, выполнить `start_windows.bat`, открыть `http://127.0.0.1:8000`. Linux/macOS: `./start_linux.sh`. Нужен Python 3.12+ и возможность установить зависимости.

**Перед обновлением действующей копии обязательно сохранить и проверить резервную копию базы**. R20 основан на восстановленной R19. Не заменять им неизвестный рабочий экземпляр, не сверив структуру и состояние. Выполнить `PYTHONPATH=backend alembic -c backend/alembic.ini upgrade head` на правильной `DATABASE_URL`.
