# R34 — инструкция руководителю по входящей очереди

Новый раздел находится в **«Контроль доставки» → «Диагностика входящих по аккаунтам»**.

## Когда аккаунт занят

Надпись **«Обработка аккаунта выполняется»** означает, что SQL-очередь выделила одному обработчику право сохранить входящие по этому подключению. Другие аккаунты могут продолжать обрабатываться. Если видите зависший захват, проверьте состояние worker и системную диагностику. Не удаляйте события ради освобождения очереди.

## Если недоступен ключ расшифрования

1. Проверьте `INTEGRATION_ENCRYPTION_KEY` и предыдущие ключи. Не вставляйте их в чат поддержки или публичные логи.
2. В **«Контроль доставки» → «Ошибки»** найдите записи с пояснением об отсутствующем ключе.
3. Восстановите ключи в серверной конфигурации и убедитесь, что они доступны API и worker.
4. Сначала проверьте один подходящий элемент. Затем используйте пакетный предпросмотр, если ошибок много.

## Массовое восстановление

1. Выберите один аккаунт с ошибками.
2. Нажмите **«Проверить до 20 ошибок»**. Система покажет точное число событий без содержимого клиентов.
3. Запишите, что было проверено, и подтвердите возврат в очередь.
4. Если ситуация изменилась или прошло 90 секунд, нажмите **«Обновить предпросмотр очереди»**, затем подтвердите новый набор.
5. Проверьте, что события появились во входящих. Сам повтор **не отправляет клиенту исходящее сообщение**.

**Важно:** никогда не подтверждайте неизученный пакет ошибок. Необратимое закрытие события с удалением шифротекста — отдельная операция, которую нельзя отменить.
