# Протокол QA OSMANX OMNICHAT R23

**Дата:** 5 ноября 2026 года. **Среда:** Python 3.13, Node.js 22, SQLAlchemy/Alembic, SQLite, реальный Chromium. Никакие настоящие аккаунты соцсетей и платёжные ключи не использовались.

## Автоматические тесты

| Группа | Фактически проверено | Итог |
| --- | --- | --- |
| Базовые API, Inbox, CRM, безопасность данных и интеграции | 65 тестов, отдельный процесс pytest | **65 / 65 успешно, exit 0** |
| История R20, команда R21, ручное управление R22, аварии R23 | 41 тест, отдельный процесс pytest | **41 / 41 успешно, exit 0** |
| Сессии, безопасность, SQL-квоты, здоровье worker | 30 тестов, отдельный процесс pytest | **30 / 30 успешно, exit 0** |
| Резервные копии, собственный веб-чат, шаблоны WhatsApp | 25 тестов, отдельный процесс pytest | **25 / 25 успешно, exit 0** |
| **Всего** | **161 тест** | **Все прошли в независимых процессах** |

Дополнительно `test_r23_crash_recovery.py` проверяет 15 новых сценариев: безопасное восстановление до запроса, защиту старого обработчика, неизвестную доставку после начала запроса, heartbeat медленного API, CAS, две конкурирующие отправки, отсутствие изменений чужой компании, миграцию старой строки `processing`, повтор после безопасного восстановления и отображение фаз работы.

**Оговорка об окружении:** один монолитный запуск `pytest -q backend/tests` и крупная объединённая группа печатали успешные результаты, но процесс не завершался самостоятельно. Для проверки выпуска все 161 тест выполнены как четыре независимых процесса, каждый с кодом завершения 0. Причина задержки teardown больших объединённых тестовых прогонов остаётся техническим долгом; CI конфигурация обновлена на четыре обязательные группы.

## База данных и миграции

- Чистое применение `alembic upgrade head` на SQLite — **успешно**.
- `alembic check` — **No new upgrade operations detected**.
- Head `f23000a10001`, два новых поля OutgoingJob подтверждены.
- Тест R22 → R23 с существующей организацией, каналом, сообщением и незавершённой попыткой — **успешно**. Старая попытка без `claim_token` была изолирована как неопределённая, не отправлена повторно.

## Настоящий браузер

`PYTHONPATH=backend python scripts/browser_r23_claim_recovery.py` с FastAPI TestClient + Chromium:

- **1512 × 950, 390 × 844, 320 × 700** — все три сценария завершились.
- Новый статус «Подготовка до отправки», индикатор безопасных восстановлений и существующие действия R22 отображаются.
- Отмена до отправки и подтверждённый ручной повтор по-прежнему выполняют SQL-операции, без внешнего API.
- JS ошибок и горизонтального переполнения в проверенных сценариях не обнаружено.

## Не подтверждено

- PostgreSQL multi-worker race под настоящей БД (**CI сценарий подготовлен, не выполнен локально**).
- Реальная доставка через соцсети, webhook-квитанции, поведение при сетевом разрыве в боевом API.
- React 19 и Vite: установку из npm остановила DNS-ошибка `EAI_AGAIN`.
- Нагрузочные испытания, внешний security-аудит, публичный HTTPS-деплой и платежи.

Этот отчёт не приравнивает локальную проверку к доказательству готовности production SaaS.
