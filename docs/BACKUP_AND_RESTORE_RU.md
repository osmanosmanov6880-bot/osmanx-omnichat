# Резервные копии OSMANX — простая инструкция

## Если используете приложение на компьютере

1. Не удаляйте старую папку и базу `omnichat.db` при обновлении.
2. Перед установкой новой версии запустите `backup_local_windows.bat` или `./backup_local_linux.sh`.
3. Дождитесь сообщения о проверенной копии. Она появится в папке `backups` вместе с `.manifest.json`.
4. Храните копию и манифест вместе, желательно в зашифрованном хранилище вне этого компьютера.
5. После обновления проверьте, что открываются ваша компания и переписки.

Начиная с v1.5, локальный стартовый скрипт сам делает резервную копию при обнаружении предстоящей миграции. Отдельное ручное копирование перед крупным обновлением всё равно полезно.

## Если подозреваете потерю данных

**Не удаляйте текущую базу. Не заменяйте её архивом наугад.**

Проверьте архив командой `sqlite-verify`, затем восстановите его в **новый** файл командой `sqlite-restore-new`. Сравните количество компаний и сообщений в тестовой копии. После этого планируйте восстановление основной базы отдельно, с остановкой приложения и сохранением обеих копий.

## Если используете Docker + PostgreSQL

Команда `./infra/backup-postgres.sh` создаёт проверенный custom-архив. Самый важный следующий шаг — **пробное восстановление в изолированную тестовую базу** и проверка сообщений. Эта процедура ещё не запускалась в текущей среде сборки, поэтому не считайте её доказанной.

Никогда не загружайте `.env`, базы данных или резервные копии в публичный GitHub. Манифест SHA-256 не шифрует данные.
