# OSMANX OMNICHAT v0.6 — Customer-Owned Channels

**Дата:** 4 ноября 2026. **Статус:** функционирующий self-hosted MVP с кодом самообслуживания компаний. **Не production**, публичного размещения, оплаты и реальных подключений не было.

## Что изменено

- Пользователь может создавать несколько отдельных компаний и переключать рабочую область; доступ к компаниям подтверждается серверными членствами.
- UI «Интеграции» на русском: пошаговая схема подключения, явные статусы, серверная диагностика, проверка прав, смена токена, инструкция обратного вызова VK. Дополнительные функции открываются по требованию, чтобы не загружать Inbox.
- Добавлен Facebook Messenger Page API (OAuth, выбор страницы с задачей MESSAGING, шифрование ограниченного по времени списка страниц, подписка на вебхуки, входящее по подписанному событию и отправка через Page token).
- WhatsApp: Meta Embedded Signup (двухшаговая активация JS SDK, чтобы браузер не блокировал popup; строгий one-time state), серверный обмен code на token, проверка Phone Number ID внутри WABA, подписка, регистрация PIN и диагностика.
- Для Авито — статус `pending_sync` до первого успешного официального чтения диалогов.
- Уникальный частичный SQL-индекс по provider/external_account_id для всех активных реальных аккаунтов: никакой автоматической передачи учётных данных между организациями. При дублях старых связей миграция останавливается до ручной проверки.
- Дополнительные поля channel connection: last_verified_at, webhook_registered_at, webhook_verified_at, token_expires_at; отдельная зашифрованная таблица временных Page selections, очистка TTL.
- Meta HMAC для Facebook Page, Instagram и WhatsApp, маршрутизация по внешнему идентификатору аккаунта к одному tenant; осторожные сроки обслуживания и карантин неопределённых отправок.
- Production startup требует защищённых cookies, HTTPS, PostgreSQL и ключа шифрования интеграций; CSP разрешает официальный Meta JS SDK только на странице приложения.
- Демо дополнено Facebook Messenger: теперь 9 тестовых диалогов из 7 социальных каналов. Веб-чат собственного сайта остаётся отдельным каналом.

## Проверка

- Backend: **45 pytest**, в том числе новые тесты многотенантности, scope/replay OAuth, Page-to-tenant routing, HMAC, duplicate event, Messenger send, WhatsApp Embedded Signup, phone registration, cross-tenant denial, encrypted credentials.
- TypeScript: `tsc --project frontend/tsconfig.json` без ошибок.
- SQLite Alembic `upgrade head` + `check` — без дрейфа.
- Chromium + реальные React-компоненты + настоящий FastAPI TestClient in-process: десктопный Inbox, демо-ответ, фильтры, 7 карточек интеграций, зарегистрированная компания с настоящей страницей onboarding, настройки нескольких компаний, мобильный чат и 320 px — без JS исключений.
- Внешние HTTP Graph/Bot запросы **в тестах имитированы**, клиентские Meta/Avito/Telegram/VK/MAX аккаунты не предоставлены. Из-за отсутствия публичного HTTPS нет подписанной сетевой поставки реальных сообщений.

## Оставшиеся критические ограничения

- Нет подтверждённых внешних OAuth/App Review/партнёрских разрешений. Наличие адаптера и контрактного теста — не факт соответствия реальным аккаунтам.
- React 16 устарел, требуется поддерживаемый стек и security review.
- Нет расширенной отправки медиа/шаблонов WhatsApp, полной синхронизации истории Instagram, реального load test и резервного восстановления PostgreSQL.
- Уникальный SaaS-tenant enforce сделан на сервере и индексах, но PostgreSQL RLS как дополнительная страховка пока не настроен.
- Нет production-проверки Docker, WAF/Redis rate limiting, независимого аудита безопасности и полного соответствия законам обработки персональных данных.
- Публикация и платежи намеренно отложены.

**Состояние проекта:** существенная часть UX и backend готова для интеграционных испытаний. Коммерческое использование не одобрено до полного тестового gate по каждому провайдеру.
