# QA OSMANX OMNICHAT R35

Дата: 6 ноября 2026. Только локальные тестовые учётные записи и синтетические события.

| Проверка | Результат |
|---|---|
| Вся серверная регрессия | **305/305 PASS**; 36 модулей, exit code 0 |
| Специальные сценарии R35 | **9/9 PASS** |
| Совместные R33+R34+R35 | **32/32 PASS** |
| Chromium с локальным FastAPI | **PASS**: desktop 1512 px, mobile 390 px, phone 320 px |
| TypeScript `tsc --project frontend/tsconfig.json` | **PASS** |
| Заполненная миграция R34 → R35 | **PASS**; старый шифротекст сохранён |
| Alembic `upgrade head`, `check` | **PASS** на заполненной SQLite из теста миграции |
| PostgreSQL реальная многопроцессная проверка | **НЕ ВЫПОЛНЯЛАСЬ локально**; код добавлен в CI |
| React 19 как рабочий runtime / боевые API | **НЕ ВЫПОЛНЯЛОСЬ** |

**Полная независимая регрессия: 305/305 тестов, 36 модулей, каждый процесс завершился с кодом 0.** Детализация: `docs/qa_r35_module_results.json`. Запуск: `PYTHONPATH=backend python scripts/verify_r35_regression.py`.

**Совместимость интерфейса R34:** повторный Chromium-сценарий подписанного массового восстановления также прошёл на 1512/390/320 px. При повторном прогоне R35 был обнаружен race в ожидании обновления DOM самого теста: добавлено явное ожидание нового счётчика, затем все три размера снова прошли. Ошибку продукта это не подтверждало.

Основные проверенные инварианты: небольшую компанию не вытесняет большая, действующая блокировка не очищается, просроченная восстанавливается с CAS, исчерпавшая попытки запись сохраняет шифротекст, пустая запись помечается без импорта, нарушение tenant/channel не чинится автоматически, lead читает диагностику без права восстановления, текст события и токены не раскрываются.

Браузерная проверка выполняла настоящий запрос POST после ручного подтверждения и проверяла конечные статусы в SQLite. Это **не скриншотный макет**.
