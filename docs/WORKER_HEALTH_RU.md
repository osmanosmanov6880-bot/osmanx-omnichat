# Работает ли отправка? Объяснение для предпринимателя

Откройте OSMANX → **«Ещё разделы» → «Контроль доставки»**. Если вы видите:

- **«Очередь обрабатывается»** — недавно завершился хотя бы один реальный цикл обработки. Это не доказательство, что конкретный клиент получил ответ: смотрите статус его сообщения.
- **«Обработчик запущен, ожидаем завершения цикла»** — сервер видит процесс, но пока нет свежей завершённой попытки. Через короткий промежуток нажмите «Проверить снова». Если статус не меняется, обратитесь к администратору сервера.
- **«Фоновый обработчик не отвечает»** — процесс не присылал отметок последние 40 секунд. При наличии ожидающих внешних ответов необходимо проверить worker/службу и сетевой доступ сервера.
- **«Нет внешних отправок для обработки»** — сейчас нет поставленных в очередь сообщений и активных внешних каналов. Остановленный фоновой обработчик для одного лишь деморежима не всегда означает проблему.

**«Нужна проверка»** в списке отправок — отдельная ситуация: площадка могла принять сообщение до потери связи. Не нажимайте повторную отправку, пока результат не проверен в оригинальном сервисе. Подтверждение API ≠ доставка клиенту.

## Для администратора системы

1. В production примените миграции Alembic **перед** запуском API и worker. Без нужной версии базы сервер откажется стартовать.
2. Для отдельного worker используйте `PYTHONPATH=backend python -m app.worker`; API worker можно отключить переменной `ENABLE_OUTBOX_WORKER=false` только если отдельный worker действительно запущен.
3. Приложение фиксирует heartbeat каждые 8 секунд. Система считает процесс активным в течение 40 секунд после последнего сигнала, а нормальным — если цикл завершился в последние 120 секунд.
4. Показатель считается глобально по обработчикам платформы, но предприятие видит **только собственные** сообщения, каналы и задания. ID процессов и хосты не выводятся.
5. Фоновые записи, не обновлявшиеся 7 дней, удаляются периодической очисткой. Эту таблицу не используйте как полный юридически значимый аудит — он находится отдельно.

### Условия, требующие отдельной проверки

При масштабировании на несколько процессов убедитесь в общем PostgreSQL, работоспособности очереди под нагрузкой, сетевой доступности всех провайдеров и наличии независимого мониторинга (например, Prometheus). Heartbeat — **сигнал здоровья**, но не гарантия SLA или доставки.
