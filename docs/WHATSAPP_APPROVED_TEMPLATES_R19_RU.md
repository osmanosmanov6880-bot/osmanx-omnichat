# Официальные WhatsApp-шаблоны — инструкция для владельца и оператора

**Назначение:** если прошло более 24 часов после последнего сообщения клиента в WhatsApp, обычный текст через Cloud API отправлять нельзя. Оператор может выбрать **одобренный в Meta** шаблон и заполнить параметры, когда есть согласие получателя. OSMANX не генерирует фальшивое «одобрение» шаблона: при запросе он обращается к официальному WABA `GET /{WABA ID}/message_templates` и отбирает только `status=APPROVED`.

## Что делает сотрудник

1. Откройте «Входящие», выберите диалог WhatsApp, нажмите **«Одобренный шаблон WhatsApp»**.
2. Укажите источник и дату ранее полученного согласия клиента и подтвердите его **только если согласие действительно есть**. Этот шаг разрешён руководителю или администратору; OSMANX фиксирует действие в аудите, но не проверяет сам юридическое основание согласия.
3. Выберите шаблон из списка, полученного от Meta, заполните переменные `{{1}}`, `{{2}}` и проверьте предпросмотр. Поддерживаются только простые текстовые BODY-шаблоны, без заголовков, кнопок, изображений и документов.
4. Нажмите **«Поставить шаблон в очередь»**. Это ещё **не означает доставку**. Сначала сообщение сохраняется в базе, после проверки доступа, согласия и актуального статуса шаблона фоновый обработчик выполняет официальный POST к Meta.
5. Если клиент отозвал согласие, руководитель может отменить разрешение в том же окне. Очередь повторно проверяет согласие перед отправкой; уже отправленные и находящиеся в момент отзыва в сетевом запросе сообщения отменить нельзя.

**Для работы нужны:** официальный WhatsApp Business Platform аккаунт, Meta Phone Number ID, WABA ID, подходящий токен доступа, одобренный шаблон, настроенный HTTPS webhook и права клиента. Наличие этих данных на локальной машине ещё не доказывает, что реальные сообщения доставляются.

## Реализованные гарантии и ограничения

- Сервер проверяет принадлежность компании, канала и диалога, роли сотрудника и optimistic version.
- Реестр согласий изолирован по компании, каналу, контакту и WhatsApp recipient ID.
- Повторный `client_nonce` при одинаковом шаблоне возвращает исходную запись, несовпадающие параметры с тем же nonce — ошибка 409.
- Перед реальным вызовом API шаблон проверяется повторно: удалённый, не одобренный или изменивший структуру шаблон **не будет автоматически отправлен**.
- После успешного API-вызова статус «принято API», не «прочитано».
- Оставшиеся в очереди сообщения с неизвестным результатом при сетевом сбое требуют ручной сверки.

Ограничения: данный выпуск проверен на локальных имитациях Meta HTTP и в Chromium, но не в реальном аккаунте и не прошёл независимый аудит безопасности. React 19 не включён: современный билд требует npm-зависимости. Публичная публикация и биллинг отложены.

**Справка Meta:** [Send Message Template Text — официальный набор запросов Meta](https://www.postman.com/meta/whatsapp-business-platform/request/o65u5m5/send-message-template-text) и документация WhatsApp Business Platform/Cloud API.
