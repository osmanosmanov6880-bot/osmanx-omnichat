- VPS: `vmi3670540`, `169.58.244.3`.

## Блокирующие проверки
1. В GitHub должен присутствовать **полный код** R36, не только README/документация: backend, migrations, frontend, тесты и lock-файлы. Сравнить с проверенной локальной сборкой.
2. Проверить `git status --short` и `git ls-files` перед push. Не добавлять `.env`, `.env.*` (кроме безопасного `.env.example`), `*.db`, `*.sqlite*`, `*.dump`, `*.pem`, `*.key`, токены, резервные копии и клиентские данные. Просканировать историю на секреты до публикации.
3. CI: установка фиксированных зависимостей, статические проверки, Python-тесты, Alembic check, frontend build; PostgreSQL-интеграционные тесты до разрешения деплоя.
4. На VPS создать **отдельного пользователя деплоя** с ключом Ed25519, ограниченными правами на каталог приложения и строго ограниченной командой systemd; проверить отдельное подключение. Не использовать root-пароль в GitHub.
5. GitHub Environment `production` с обязательным подтверждением; Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. SSH host key проверить вне канала подключения, а не принимать автоматически.
6. Перед релизом: резервная копия PostgreSQL и верификация восстановления, проверка шифровального ключа без вывода его значения, сохранение server-side `.env`. Никогда не копировать SQLite через GitHub.
7. Деплой только из проверенного immutable commit SHA, с staging-директорией, миграциями по процедуре релиза и контролируемым переключением. Проверка `systemctl is-active`, HTTP health маршрута, Telegram webhook; откат приложения при ошибке, с учётом **необратимости некоторых миграций БД**.

## Безопасная публикация исходников из Windows PowerShell
В локальном каталоге проекта выполнить сначала:
```powershell
git status --short
git remote -v
git ls-files | Select-String -Pattern '(\.env$|\.db$|\.sqlite|\.dump$|\.pem$|\.key$)'
```
При обнаружении секретов остановиться и очистить индекс/историю; не делать `git add -f`. Для первоначальной загрузки использовать отдельную ветку и pull request, не заменять действующий main вслепую.

## SQLite -> PostgreSQL
Файл `/root/omnichat-import.db` ранее был 0 байт и не является пригодным источником. Проверять SHA-256, размер и `PRAGMA integrity_check` после отдельной защищённой передачи; импорт проводить с проверкой FK, количеством записей и ключом шифрования, без публикации данных в GitHub.
