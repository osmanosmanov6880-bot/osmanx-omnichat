# OSMANX OMNICHAT R22 — управление отправкой без ложных обещаний

**Релиз:** 5 ноября 2026 года. **Статус:** проверенный локальный MVP. Не заявляется работающим production SaaS, внешние аккаунты не подключались.

## Что реализовано непосредственно в коде

### 1. Отмена исходящего ответа, пока он не отправлен

В «Контроль доставки» у заданий со статусом **«В очереди»** появилась кнопка **«Отменить до отправки»** для владельца, администратора и руководителя.

Обработка выполняет атомарную операцию compare-and-swap в общей базе: `queued → cancelled`. Если второй процесс уже захватил задание (`processing`), сервер возвращает HTTP 409 и **не обещает отмену**. Одновременно проверяются организация, канал, беседа и статус исходящего сообщения. При успешной отмене статус сообщения становится `cancelled` и в журнале остаётся запись сотрудника. Больше это сообщение фоновый обработчик не отправляет.

**Отмена не удаляет историю переписки** и не применяется к статусам `processing`, `uncertain`, `failed`, `done`.

### 2. Ручной повтор — строго после явного отказа площадки

Только владелец и администратор могут использовать **«Повторить после проверки»**. Рядом с ошибкой должна быть подтверждённая площадкой ошибка API **400/401/402/403/404/405/410/412/413/415/422**, сообщение должно иметь статус `failed`, а канал — оставаться подключённым. Запрос требует подтверждения отсутствия доставки и содержательного пояснения минимум на 12 символов. Пояснение фиксируется в аудите.

Повторы **ЗАПРЕЩЕНЫ** для `uncertain`, `processing`, `done`, API 408/409/429, 5xx, ошибок с непроверенной доставкой и сообщений с настоящим `external_id` площадки. Если менеджер ранее вручную пометил неопределённую доставку как ошибку, это не превращает её в однозначный отказ API.

Созданный браузером `client-<nonce>` — **локальный идентификатор дедупликации**, не подтверждение провайдера; он не мешает безопасному повтору. После явного ручного решения задача вновь переходит в `queued` и снова проходит все штатные проверки канала, окна ответа, согласия WhatsApp и прав доступа в обработчике. Это ещё **не доставка**.

### 3. Минимальный тёмный интерфейс

В обычном разделе «Контроль доставки» добавлены две кнопки только для применимых состояний. Перед отменой браузер запрашивает подтверждение. При повторе открывается короткая форма с описанием проверки и отдельной галочкой. Счётчик отменённых заданий расположен компактно над таблицей, а не в дополнительной крупной карточке. Отдельные вкладки и сложные настройки не добавлены.

### 4. Серверные гарантии и аудит

- Проверки прав (`owner`, `admin`, `lead`) и жёсткая привязка каждого задания к организации.
- Конкурентное изменение статуса задания с проверкой исходного `queued`/`failed`; при проигранной гонке возвращается 409.
- Состояние исходящего сообщения изменяется в той же транзакции, что и задача.
- Аудит успешной отмены и проверенного ручного повтора; никогда не копируем секреты провайдеров в результат операций.
- `cancelled` включён в список и агрегаты статусов. Отмена доступна по ID только внутри своей компании.
- Без изменений ORM-структуры. **Новая миграция Alembic не требуется** — существующее поле статуса хранит строковое значение.

## Проверки

[QA_R22_RU.md](QA_R22_RU.md) описывает фактические проверки. Новые сценарии `test_r22_outbox_control.py` (10) включают успешную отмену, атомарную гонку, строгие роли, защиту другой компании, отсутствие повторной отправки при неопределённом результате и прохождение проверенного повтора через mock-провайдер. Браузерный сценарий `browser_r22_outbox_control.py` проверяет кнопки на ПК, 390 и 320 px с настоящим локальным FastAPI.

## Границы

- **Нет реальных тестов WhatsApp/Instagram/Авито в этой среде.** Статус `accepted` после API не означает доставку или прочтение человеком.
- PostgreSQL-сценарий с конкурирующими процессами добавлен в CI, но локально PostgreSQL/Docker не запускались. До проверки workflow нельзя заявлять готовность многосерверного production.
- Подготовленный React 19 пока не прошёл загрузку npm-зависимостей; проверенная работающая сборка остаётся на React 16.
- Нет новых платежей и публичного деплоя. Релиз продолжается из R21; если у вас уже есть рабочая база, сохраните её резервную копию и проверьте ревизию схемы перед обновлением.
