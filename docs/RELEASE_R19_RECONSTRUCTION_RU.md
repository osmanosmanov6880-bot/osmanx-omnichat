# OSMANX OMNICHAT — R19 Recovery + Approved WhatsApp Templates

**Дата:** 4 ноября 2026 года. **Статус:** локально тестируемый восстановленный релиз; **НЕ** проверенный production SaaS.

## Откуда исходники и что означает «восстановленный»

Исходный ZIP v1.8 предыдущего шага **не сохранился в рабочем окружении и не был найден в доступной библиотеке файлов**. Для настоящей разработки использован сохранённый архив **OSMANX_OMNICHAT_SAFE_RECOVERY_v1.5.zip**. На его основе воспроизведены основные механизмы v1.6–v1.8 (распределённые lease для фоновых задач, ограничение 429 по каналу, подтверждение доставки виджета, защита подписанных Meta webhook-пакетов) и добавлены официальные текстовые шаблоны WhatsApp в R19.

**Это не побайтовое восстановление v1.8!** Не заменяйте этим архивом единственную рабочую копию приложения без сверки с прежним ZIP и резервной копии базы. Восстановление функциональных блоков подтверждено тестами, не идентичностью исходных файлов.

## Новая функция — WhatsApp approved text templates

- `GET /api/conversations/{id}/whatsapp-templates` — реальные одобренные Meta WABA шаблоны, простой BODY-текст без кнопок и media.
- `POST /api/conversations/{id}/whatsapp-consent` и `.../revoke` — вручную зафиксированное и отзывное согласие; это не доказательство в Meta.
- `POST /api/conversations/{id}/whatsapp-template` — tenant-scoped, RBAC, optimistic lock, идемпотентный nonce, серверный подбор одобренного шаблона и подстановка переменных.
- Отдельная ветка outbox повторно проверяет статус шаблона и согласие до **официального** Meta POST; запрос с ненадёжным результатом не отправляется повторно автоматически.
- Тёмный российский интерфейс — кнопка рядом с обычным ответом, понятное окно предпросмотра, учёт согласия и история очереди.

## Воссозданные ключевые изменения v1.6–v1.8

- Атомарная SQL-координация фоновой синхронизации Авито/очистки данных между worker-процессами.
- Пауза на отдельный канал при HTTP 429 с Retry-After; другие компании продолжают работу.
- Веб-чат сайта: `accepted` → `delivered` только после безопасного подтверждения посетительским браузером, повторное использование nonce после оборванного HTTP-ответа.
- Защита webhook Meta от некорректной структуры, чрезмерных пакетов и плохих timestamps.

## Миграции

От официально сохранённой v1.5 ревизии `ee4a14b80001` цепочка:

`f1660001c001` → `fa170001c001` → `f19000a10001`.

В новой таблице `whatsapp_consents` хранится ручное подтверждение согласия для канала и получателя. Существующие компания и канал при тестовом обновлении сохранены. **Перед обновлением сделать проверенную резервную копию и выполнять Alembic upgrade head.**

## Результаты локальной проверки

125 backend-тестов пройдены; TypeScript компилируется, Chromium с настоящим React-кодом и локальным FastAPI проверен на ПК/390/320 px. Alembic применяет миграции и не обнаруживает ORM-drift. Отчёт: `docs/QA_R19_RECOVERY_RU.md`.

## Честные границы

- Реальные WhatsApp, Instagram, Авито, Telegram, VK, MAX и Messenger **не подключались** в данном тесте; сценарии Meta HTTP имитируются. При установке клиентских токенов/доступов требуется авторизация, права, HTTPS, webhook и живой сквозной тест.
- React 16 остаётся действующей сборкой; экспериментальная React 19/Vite требует npm, который в этом окружении недоступен.
- PostgreSQL/Docker под нагрузкой, платёжная система, публичная публикация и независимый аудит безопасности не выполнялись.
- Не были восстановлены из недоступного архива все возможные байтовые отличия v1.8, поэтому обязательна сверка с вашей последней копией перед применением к рабочей базе.
