# Каналы OSMANX OMNICHAT — подключение без обходов API

Пользователь попросил: «отвечать из одного приложения во все соцсети». Технически это возможно для **поддерживаемых бизнес-аккаунтов, ботов и сообществ, разрешивших API-доступ**, а не всех личных переписок произвольных пользователей. Внутри приложения история нормализуется в одни `Conversation` / `Message`; ответ всегда передаётся адаптеру **того же источника**, где был создан диалог.

## Перед использованием боевых ботов

1. Создайте **обычную рабочую организацию**, не Demo Mode.
2. Настройте `INTEGRATION_ENCRYPTION_KEY` в серверном `.env`. Ключ нельзя публиковать в GitHub.
3. В будущем после отдельного этапа развёртывания включите HTTPS и `PUBLIC_BASE_URL=https://...` (локальное демо работает без него).
4. В разделе **Ещё разделы → Интеграции** выберите Telegram, ВКонтакте или MAX и нажмите «Подключить».
5. Введите действительный официальный токен; VK также требует ID сообщества и код подтверждения Callback API. После проверки аккаунт получает статус **«Ожидает webhook»**.
6. Telegram/MAX: нажмите «Настроить webhook» — сервер вызовет официальную подписку только после явного действия; для VK вручную добавьте предоставленный адрес и одноразовый секрет в настройки Callback API сообщества.
7. Отправьте боту/сообществу тестовое сообщение от разрешённого пользователя. **Только подтверждённый входящий webhook** переводит канал в подключённый статус.
8. Откройте полученный диалог, отправьте ответ, проверьте его доставку у провайдера. Если результат неопределён, разберите его в разделе контроля доставки до ручной повторной отправки.

Демо-каналы показывают все те же основные действия без доступа к реальным платформам. При выключенной публикации настоящие внешние webhooks недоступны: это ожидаемое ограничение.

## Технические и юридические ограничения

- Один бот Telegram не даёт доступ к личной переписке пользователя в его аккаунте. Telegram может расширять бизнес-возможности отдельно; нельзя предполагать, что такой доступ предоставлен автоматически.
- VK: подключаются разрешённые сообщения **сообщества**, не личный аккаунт. Поддержка официальных callback-событий не означает, что у токена уже есть все необходимые права на отправку.
- MAX: нужен именно бот, ему доступна только переписка, разрешённая платформой. Сервер подписки должен использовать официальный HTTPS и соблюсти требования сертификатов; в документации MAX указан хост `platform-api2.max.ru`.
- Instagram: нужен профессиональный аккаунт с соответствующими разрешениями Meta; WhatsApp: WhatsApp Business Platform и обслуживание в допустимых окнах.
- Внешний API может менять правила, права доступа, лимиты и набор поддерживаемых вложений. На момент этого релиза **ни один реальный токен не предоставлялся**.
- Не объединять идентичности клиентов по одинаковому имени между соцсетями. Система хранит отдельные внешние идентификаторы и допускает контролируемое ручное объединение.
