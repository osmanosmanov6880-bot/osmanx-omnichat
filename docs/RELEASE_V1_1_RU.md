# OSMANX OMNICHAT v1.1 — Secure Operations

**Статус:** локальная self-hosted версия с новым блоком безопасности входа и повышения надёжности Web Chat. **Это не сертификат production-готовности** и не подтверждение отправки сообщений из реальных аккаунтов соцсетей.

## Что сделано

1. **Серверная защита входа.** Неудачные авторизации учитываются в таблице `login_failures` и действуют между несколькими API-процессами, подключёнными к одной базе. Для каждой нормализованной почты введено ограничение 10 неудачных попыток за 15 минут. Учётные идентификаторы представлены HMAC-SHA256, если настроен серверный секрет; пароль или email открытым текстом в журнал не добавляются. При успешном входе счётчик очищается. Старый IP-limiter остаётся дополнительной защитой. Под предельной конкурентной нагрузкой атомарная межпроцессная защита попыток ещё требует отдельной проверки и может быть усилена Redis/DB advisory locks.
2. **Управление сеансами пользователя.** `GET /api/auth/sessions` отдаёт только время создания и признак текущего сеанса. `POST /api/auth/sessions/revoke-others` закрывает сеансы других устройств. `POST /api/auth/sessions/revoke-all` отзывает все сеансы текущего пользователя, включая действующий, и удаляет cookie. Полные session-токены из API не выдаются. Действия записываются в аудит.
3. **Веб-чат при перезапуске нескольких API.** Для каждого посетителя дополнительно действует лимит 90 входящих за скользящий час, рассчитанный по сообщениям в общей БД; он сохраняет действие при очистке памяти сервера. Повторный запрос с тем же `client_nonce` возвращает исходное сообщение даже при достижении лимита, не создавая дубликата.
4. **Оптимизированы WhatsApp-квитанции.** Поиск сообщения по внешнему ID использует SQL JOIN с ограничением по компании **и конкретному каналу** вместо загрузки всех ID диалогов в память; квитанция чужой компании ничего не меняет.
5. **Тёмный русский UI сохранён.** В разделе «Настройки → Безопасность входа» появились три простые кнопки для просмотра и отзыва сеансов. Основной Inbox, CRM и мастера соцсетей не перегружены.

## Проверка

- 7 новых тестов: запрет перебора входа, хранение псевдонимов, успешный вход после ошибки, отзыв отдельных и всех сеансов, защита от CSRF, изоляция WhatsApp-квитанций, Web Chat лимит и безопасный повтор запроса. Некоторые сценарии сгруппированы в один тест.
- Полный набор Python-тестов: **78 тестов** (после финального прогона; см. CI).
- Реальный React UI в Chromium с FastAPI TestClient: экран настроек, действие кнопок, повторный вход; три ширины 1512, 390 и 320 px, ошибок JavaScript/горизонтального переполнения не обнаружено.
- TypeScript: компилируется локально; JS реально пересобран в `frontend/public/app.js`.
- Миграция Alembic v1.0 → v1.1: сохранены тестовые организация и канал, схема соответствует ORM.
- Всё это **локальные и моделируемые интеграционные проверки**, без боевых токенов соцсетей.

## Как запустить

Обычный запуск Windows: `start_windows.bat`. Linux/macOS: `./start_linux.sh`. Откройте `http://127.0.0.1:8000`. Для демо нажмите «Демоверсия», для собственной компании — «Регистрация». Python 3.12+ и доступ к установке зависимостей требуются при первом запуске.

При переходе со старой базы сначала сделайте резервную копию, затем выполните `alembic -c backend/alembic.ini upgrade head`. Старый файл базы в ZIP не включён.

## Что намеренно НЕ готово

- Авито, Instagram, WhatsApp, Telegram, VK, MAX и Messenger не проверены с реальными учётными данными пользователей в этом релизе. Для фактического подключения нужны официальные права, HTTPS webhooks, корректные ключи и сквозной тест в каждой оригинальной соцсети.
- Не обновлён React 16: npm-реестр оказался недоступен из данной среды. Это **блокер перед боевым публичным запуском**. Нет подтверждённого React 19 build/pentest.
- Не проверены в целевой инфраструктуре горизонтальное масштабирование worker, PostgreSQL и Docker. Нет результатов полноценного нагрузочного теста и независимого пентеста.
- Публичная публикация, оплаты и списание подписки не выполнялись по запросу владельца.
