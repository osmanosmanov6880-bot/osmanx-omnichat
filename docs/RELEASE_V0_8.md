# OSMANX OMNICHAT v0.8 — REAL CONNECT READINESS

**Дата:** 4 ноября 2026 г.  
**Статус:** self-hosted MVP с локально проверенной логикой подготовки официальных каналов. **Не коммерческий production; реальные бизнес-аккаунты не подключались.**

## Реально внесённые изменения

1. **Достоверная диагностика четырёх этапов** в `backend/app/integrations/readiness.py`: подтверждение аккаунта, настройка событий, фактическое входящее, внешний API принял исходящее. Демо не считается живым подключением.
2. **Серверная сверка Telegram/MAX** в `backend/app/integrations/subscription_check.py`: `getWebhookInfo` и `GET /subscriptions`, строгий матч HTTPS callback. При несовпадении подключение не объявляется готовым; проверка требует владельца/администратора нужной компании.
3. **Сервер хранит маркеры подтверждений** `webhook_provider_verified_at`, `outbound_api_accepted_at`; миграция Alembic `e15caa761102` совместима с существующей базой. Исторические сообщения не выдаются за подтверждение новых секретов.
4. **Повторная проверка прав** не сбрасывает успех отправки, **смена токена** сбрасывает подтверждение отправки и (для ботов TG/MAX) заново требует подписку/webhook.
5. **Простой интерфейс подключения** в настоящих компонентах React/TypeScript: «Этапы: 1 из 4», подробная подсказка что делать дальше, кнопки проверки подписки и прав, раскрываемые второстепенные операции, без фальшивого зелёного статуса.
6. **Локальный preflight** `scripts/check_live_setup.py` проверяет HTTPS URL, настройки Fernet, безопасные cookies/PostgreSQL в production и параметры приложений. Не отправляет токены и не обращается к платформам.
7. **Корректное отключение Telegram/MAX:** сначала официальное удаление webhook и контроль через API, только потом локальное удаление токена. При сетевой ошибке учётные данные остаются для повторной попытки. Другие площадки явно требуют отзыва доступа в их кабинете.
8. **Полное русскоязычное руководство** для владельца платформы и компаний: `docs/CONNECT_REAL_CHANNELS_V08.md`.

## Проверки

- **59/59 pytest** — API/права, подписи webhook, дедупликация, защита арендаторов, outbound, дополнительная диагностика.
- TypeScript: `tsc --project frontend/tsconfig.json` — успешно.
- Alembic: новая база → head → check успешно; обновление v0.7 → v0.8 с сохранением организации и канала → check успешно.
- Chromium: реальный React через FastAPI TestClient — 4 этапа подключения, 7 каналов, статусы, переходы и отсутствие ошибок JS. Снимок `docs/preview-v08-onboarding.png`.
- Chromium Inbox: ПК 1648px и мобильные экраны 390px, 320px, горизонтальное переполнение 0px; операции ответа, заметки, теги и статус сделки через реальный backend.

**Ограничение QA:** Browser E2E использует local in-process HTTP bridge, а ответы сторонних API симулируются. Это не живое испытание Meta/Авито/Telegram/MAX или Интернет-доставка. Исходящие приняты API ≠ доставлены клиенту.

## Не включено в релиз

- Нет настоящих разрешённых бизнес-аккаунтов и сквозных испытаний внешних API.
- Нет полноценных медиа-ответов и approved templates WhatsApp за пределами окна обслуживания.
- Нет публичного сервера/HTTPS, production PostgreSQL/Docker испытаний, Redis/горизонтального масштабирования.
- React 16 всё ещё устарел — **блокер production security-review** до перехода на поддерживаемый стек.
- Биллинг, публичная публикация и общение с реальными клиентами намеренно отложены.

**Оценку готовности production в процентах не устанавливаем:** частичные контрактные тесты не доказывают готовность реальной эксплуатации.
