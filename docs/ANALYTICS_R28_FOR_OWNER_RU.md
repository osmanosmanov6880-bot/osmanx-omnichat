# Аналитика OSMANX R28 простыми словами

## Почему система не должна считать «нажал Отправить» ответом

Представьте: оператор написал клиенту, но Instagram временно ограничил API. Сообщение осталось в очереди 20 минут. Клиент ответа не получил. Если считать момент нажатия кнопки успешной реакцией, владелец увидит прекрасную статистику при реальной проблеме с обслуживанием.

**Теперь OSMANX считает отдельно:**

- **Ожидает ответа** — сообщение ещё не принято API или не отображено в чате сайта. Даже если текст уже написан, задача не закрыта.
- **В очереди** — сообщение сохранено, обработчик ещё не завершил сетевой запрос.
- **Требует проверки** — API отказал либо результат мог быть получен площадкой, но OSMANX не получил достоверного подтверждения. При неопределённом результате не нажимайте «повторить» без проверки в соцсети — можно отправить дубль.
- **Принято API** — площадка подтвердила получение запроса. **Не означает**, что человек уже увидел или прочитал сообщение.
- **Доставлено / прочитано** — только при отдельном подтверждении поддерживаемого канала. В веб-чате «доставлено» означает, что виджет отобразил ответ, но человек мог его не прочитать.

## Что смотреть руководителю

В разделе «Аналитика» проверьте число **ожидающих подтверждённого ответа**, затем число сообщений **в очереди** и **требующих проверки**. Если есть просрочка SLA, откройте «Центр управления», чтобы найти диалоги. Если ответ застрял, проверьте «Контроль доставки» и состояние каналов. Сначала устраняйте причину, а не очищайте красный показатель вручную.

Среднее «Принятие ответа» строится только на новых событиях с достоверным временем подтверждения, начиная с R28. Для старых данных может отображаться «—» — это означает **нет подтверждённой временной метки**, а не нулевое время ответа. Демопространство специально помечается как демонстрационное.

**Ограничение:** это операционные показатели на основе сообщений, а не независимая гарантия того, что клиент прочитал текст или компания получила выручку.
