# Очередь OSMANX: что изменилось для компании

Ваши сотрудники продолжают отвечать клиентам в одном Inbox. **Никаких новых обязательных кнопок** для операторов нет.

Если два сотрудника отправляют сообщения через один аккаунт соцсети, OSMANX больше не начинает два независимых внешних запроса одновременно: ответы проходят через общий SQL-слот аккаунта **последовательно**. Это уменьшает риск ограничения скорости API и помогает сохранять очередность сообщений.

В «Контроль доставки» появился небольшой показатель **«Сейчас отправляют»**: он показывает число аккаунтов вашей компании, занятых реальной попыткой отправки. Содержимое сообщений, токены и информация чужих компаний туда не попадают. Пока запрос не подтверждён API, показанный статус **не означает доставку клиенту**.

Если администрация включила аварийную паузу R25/R26, новые запросы не отправляются. Отмена до HTTP-перехода и ручная проверка неопределённых отправок по-прежнему работают. Нельзя просто повторить запрос после таймаута: клиент мог получить первое сообщение.

При обновлении действующей установки обязательно остановить старых обработчиков и сделать резервную копию. Сборка R27 предназначена для локальной проверки; настоящие сторонние аккаунты в тестах не использовались.
